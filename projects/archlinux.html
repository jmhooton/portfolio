Arch Linux

My Linux system, configuration and administration

Background

About one year ago I installed Arch Linux to be my main OS, replacing Linux Mint which up until that point was my main daily driver for a couple years. Overall I have been running a version of Linux for about 3 years.

This project will showcase my current system, how I use it, manage it, and what I learnt during that time.

My System

Distribution: Arch Linux
File System: Btrfs
Init System: systemd
Display Protocol: Wayland
Compositor/Window Manager: Sway
Terminal Emulator: foot
Shell: zsh
Application Launcher: wmenu

Btrfs

I use the copy-on-write filesystem Btrfs, over the more commonplace ext4 because of the many additional neat features it provides. Some of those being subvolumes, transparent compression, checksumming and most famously snapshots/rollbacks. Filesystems such as ext4, while probably more stable and reliable, lack many of these conveniences, which is why I chose Btrfs.

systemd

Arch Linux comes with systemd as its service management and init system. I use commands like systemctl for managing services and other commands like journalctl to inspect system log files when things go awry.

Wayland and Sway

Wayland is the display protocol I use with Sway as the compositor for my graphical environment. Because I wanted the newer and more modern display technology with better application isolation, I went with Wayland over the older, increasingly being replaced by the former, X11. Like my previous Mint installation, I used a tiling window manager for the increased efficiency and snappy workflow it allows; only difference being using Sway (Wayland compositor) over dwm (X11 window manager).

foot and zsh

foot (originating from foo-terminal), is a simple and fast terminal emulator for Wayland. I chose it as it was more slim and lightweight relative to the other current Wayland terminal emulators available. And no terminal emulator is complete without a shell to go along side, for this I chose zsh, as while not as lightweight as my terminal emulator, its features like history, globbing, customisation, autocomplete and others make up for it.

wmenu

wmenu is a ultra light application launcher that allows one to launch programs via text after a keybind similar to Windows Start and MacOS Spotlight Search. wmenu is a Wayland port of a very famous and minimal program, dmenu.

The Command Line and System Administration

When using Linux one thing you will have to get quickly comfortable with is using the terminal/command line to do day to day computer management and administration; rather than using entirely graphical tools. Common uses are navigating files, investigating services, managing packages, all different kinds of troubleshooting and checking system diagnostics.

Files and Navigation

pwd
ls
cd ~/Files
mkdir Directory
touch newfile.txt
cp file.txt Directory/
mv file.txt Directory/
mv oldname.txt newname.txt

pwd prints a full path to the current working directory, ls lists files and directories, cd changes the current working directory. mkdir and touch create new directories and empty files respectively. To copy, "cut" and rename files, there is cp and mv, cp being short for copy, and mv being short for move.

Here some common PowerShell equivalents would be Get-Location, Set-Location, New-Item, Copy-Item, Move-Item.

Text Search and Inspection

grep "error" log.txt
find ~/Directory -name "*.txt"

Use grep to search input for lines matching a pattern, be it from a file, or from a pipeline. It's very common to use grep when searching for particular lines in config files, logs and general command output. The find command acts on directories, searches through them and finds selected files.

Pacman, the AUR, and Package Management

sudo pacman -Syu
pacman -Ss firefox
pacman -Qi firefox

Pacman is the Arch Linux package manager, and one of the biggest reasons people use Arch Linux over other distributions. What makes it special is its speed combined with Arch's rolling-release update model. I use it to update, remove, search through and manage my packages on my system. The AUR or "Arch User Repository", is another reason so many choose Arch over other Linux distributions. It is a community maintained, user-submitted, massive collection of 10s of thousands of build scripts for your system.

Services and Logs

systemctl status NetworkManager
journalctl -u NetworkManager -b

I use systemctl to manage and investigate systemd services. For example I can check whether NetworkManager is currently running, start it, restart it, stop it and configure whether it starts automatically at boot; and when troubleshooting, journalctl provides the logs necessary to find out what's gone wrong.

Networking

ip addr
ip route
ping 1.1.1.1

ip addr shows you network interfaces and addresses, ip route shows the routing table and ping sends ICMP echo requests to an IP. These are the standard commands used when checking network information and diagnosing what's working or failing.

Filesystems and Storage

lsblk -f
mount
findmnt
df -h

lsblk lists hard drives, SSDs, USBs, how they are partitioned and supplying the size of them; the -f flag can show additional filesystem info. mount mounts filesystems to your system; commonly in the /mnt directory. findmnt finds and lists currently mounted filesystems in your terminal. df -h lists how much disk space is free in a human readable format via the -h flag (shows GB/MB rather than bytes).
