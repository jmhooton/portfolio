Windows Troubleshooting and PowerShell

Windows troubleshooting, diagnostics and PowerShell

Overview

This project documents a few common Windows troubleshooting scenarios one may encounter, all done in a Windows 11 virtual machine. I purposefully created problems involving DNS, NTFS permissions and the Spooler Windows service. I then worked through how I'd approach each problem if I were to encounter them, using PowerShell and builtin Windows Tools. This was all done in a VMware virtual machine as to experiment and break things without affecting my main Windows installation.

DNS Resolution

Problem

I deliberately changed the Windows network adapter to use an invalid DNS server. After I changed the configuration, Windows could still connect with external IP addresses, though domain names no longer could be resolved.

I first confirmed that general connectivity was working with:

Test-Connection 1.1.1.1 -Count 1

However:

Resolve-DnsName github.com

Investigation

Because communication with 1.1.1.1 was successful, I knew the general internet connectivity itself was still ok. This implicated the fault was specifically related to DNS rather than the more general internet connectivity.

Therefore I checked the configured DNS servers with:

Get-DnsClientServerAddress

I found out the current adapter was configured to use 192.0.2.1, which was the incorrect DNS server address I had inputted.

Cause/Fix

The problem was caused by a manually configured incorrect DNS server on the network adapter.

I fixed and restored the DNS configuration with:

Set-DnsClientServerAddress -InterfaceAlias "Ethernet0" -ResetServerAddresses

Verifying

After running the fix I checked to see DNS was indeed working now:

Resolve-DnsName github.com

Once again, the DNS look up was successful and returned me a IP address from github.com, thus verifying DNS resolution has been restored.

NTFS Permissions

Problem

For this second scenario, I created a test directory and test file and configured an NTFS permission to prevent a test user from reading or executing the directory and files contents.

When logged in as the TestUser, my attempt to read the file with:

Get-Content C:\TestDirectory\Test.txt

resulted in me getting a access denied error message.

Investigation

The file seem to exist in the expected location, thus I investigated the directories NTFS access control list with icacls: 

icacls C:\TestDirectory

The output showed me an explicit deny for TestUser. Therefore explaining why I couldn't read this specific file with Get-Content.

Cause/Fix

The problem was caused from a explicit deny ACE applied to my TestUser. I removed the deny entry via: 

icacls C:\TestDirectory /remove:d TestUser

Here the deny entry has been stripped from TestUser without touching any of the other permissions for this directory.

Verifying

I logged back into TestUser and repeated the Get-Content command from earlier:

Get-Content C:\TestDirectory\Test.txt

The contents of the file displayed to the terminal correctly, and confirming that TestUser has had their permissions restored.

Print Spooler

Problem

For this third case I simulated a printing related issue by stopping the Windows Print Spooler service.

The service was stopped using:

Stop-Service Spooler

Investigation

I checked Print-Spoolers service status with:

Get-Service Spooler

The output reported that the service currently had the Stopped status.

Additionally I also checked it's startup config:

Get-Service Spooler | Select-Object StartType

This confirmed whether or not Spooler might have been stopped from it's startup configuration aka whether it was automatic at boot and whether something happened after boot and now that changed that. Since if it was manual at boot, that would have given me a good reason why Spooler may currently be stopped.

Cause/Fix

The printing issue was caused by the Spooler service not running.

I restarted Spooler using:

Start-Service Spooler

Verifying

Once again I checked Spooler with Get-Service:

Get-Service Spooler

And the Spooler service's status has been returned to Running, verifying the service has been restored.

PowerShell Diagnostic Script

Purpose

Along with the troubleshooting scenarios, I created a PowerShell script for basic network config and connectivity verification.

The script is used to identify the current network interface, display useful configuration information such as the IPv4 address, default gateway, DNS Server and IP prefix. And run a few connectivity tests to check everything is working ok. 

$network = Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway }

Write-Host "Interface: $($network.InterfaceAlias)"
Write-Host "IP:        $($network.IPv4Address.IPAddress)"
Write-Host "Gateway:   $($network.IPv4DefaultGateway.NextHop)"
Write-Host "DNS:       $($network.DNSServer.ServerAddresses)"
Write-Host "Prefix:    /$($network.IPv4Address.PrefixLength)"
if (Test-Connection 1.1.1.1 -Count 1 -Quiet){
    Write-Host "Internet:  OK"
}
else {
    Write-Host "Internet:  Failed"
}

if (Test-Connection $network.IPv4DefaultGateway.NextHop -Count 1 -Quiet){
    Write-Host "Gateway:   OK"
}
else {
    Write-Host "Gateway:   Failed"
}

$https = Test-NetConnection github.com -Port 443 -WarningAction SilentlyContinue
if ($https.TcpTestSucceeded) {
    Write-Host "HTTPS:     OK"
}
else {
    Write-Host "HTTPS:     Failed"
}

if (Resolve-DnsName github.com -ErrorAction SilentlyContinue){
    Write-Host "DNS:       OK"
}
else {
    Write-Host "DNS:       Failed"
}

How does it work?

The script uses Get-NetIPConfiguration to retrieve network info and filters it for an interface that also has a default gateway; this avoids selecting otherwise disconnected or currently unused adapters.

It then performs multiple checks with if else conditional logic testing different connections. The first test with "Gateway" is for whether I can reach the default gateway, the second with "Internet" is whether I can connect to an external IP without using the DNS server, the third test "DNS" tests whether I can get name resolution, and the fourth and final test tests whether I can connect to a HTTPS port over TCP.

So if one of these tests fail, it helps me narrow down which part of connectivity might be causing the problem.

What I Learned

This project and just my general Windows study, gave me practical experience troubleshooting and diagnosing serveral different types of Windows related problems rather than only knowing and applying predefined solutions. Here I demonstrated the ability to isolate DNS from general connectivity, how to check NTFS permissions and to grant and revoke them, and how to manage Windows services if for some reason Spooler (among other services) is broken again.

I also learnt a lot of PowerShell and how it works as it passes Objects rather than text like Bash or other shells; which was a lot of fun and extremely interesting. Overall I feel like I have improved my understanding of Windows and troubleshooting from my learning.
